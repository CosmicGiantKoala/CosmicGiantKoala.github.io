Representative Project 01

RFist

3D 멀티플레이 대전 격투 액션 게임

핵심 어필

Photon Fusion2 기반으로 캐릭터 입력, 상태, 수명주기, 전투 이벤트를 동기화하는 멀티플레이 액션 게임 클라이언트 시스템을 구현했습니다.

역할Unity 클라이언트 개발
담당 시스템HeroNetworkSystem, HeroControlSystem
주요 기술Unity, C#, Photon Fusion2, Input System, DOTween
개발 범위네트워크 입력, 영웅 상태 동기화, 캐릭터 수명주기, 조작 시스템 연결

담당 업무

  • Photon Fusion2 기반 영웅 캐릭터 네트워크 동기화 시스템 설계 및 구현
  • 로컬 입력 수집, 네트워크 입력 전송, 원격 클라이언트 동작 반영 구조 구현
  • HP, SP, 경직 포인트, 자세 상태 등 전투 상태의 네트워크 동기화 처리
  • 영웅 오브젝트 스폰/디스폰, 능력 변경, 컴포넌트 초기화 흐름 관리
  • 캐릭터 조작 시스템과 네트워크 시스템 간 연결 구조 구현

주요 구현 포인트

  • NetworkHeroObject: 캐릭터 수명주기 및 하위 시스템 통합 관리
  • NetworkHeroStatus: HP/SP/경직/자세 상태 동기화
  • NetworkHeroInput: 로컬 입력 수집 및 네트워크 입력 전송
  • NetworkHeroController: 네트워크 입력 수신 후 실제 캐릭터 조작 실행
  • 이벤트 기반 구조로 UI, 전투, 애니메이션 시스템 간 결합도 감소

기술적 문제

멀티플레이 액션 게임에서는 입력 지연, 상태 불일치, 캐릭터 수명주기 관리가 복잡해질 수 있었습니다.

해결 방식

NetworkHeroObject를 중심으로 상태, 입력, 능력, 이벤트를 통합 관리하는 Facade 구조를 구성했습니다. 입력은 NetworkInput과 RPC를 통해 전달하고, 상태는 Networked 속성과 ChangeDetector를 활용해 변경 시점에 맞춰 동기화했습니다.

게임 클라이언트 역량으로 연결되는 지점

실시간 멀티플레이 액션 게임에서 중요한 입력 처리, 상태 동기화, 캐릭터 수명주기 관리 경험을 갖추고 있습니다. 단순 기능 구현이 아니라 네트워크 환경에서 일관된 플레이 상태를 유지하기 위한 구조 설계에 집중했습니다.

Representative Project 02

Slime Rush

Steam 출시 로그라이크 액션 핵앤슬래시 게임

핵심 어필

출시 게임에서 플레이어 경험에 직접 연결되는 전투 시스템과 업적 시스템을 구현했습니다.

플랫폼PC / Mac / Steam
역할Unity 클라이언트 개발
담당 시스템BattleSystem, AchievementSystem
주요 기술Unity, C#, Zenject, Localization, Steam 플랫폼 대응

BattleSystem 구현

  • MagicBookLibrary: 플레이어가 보유한 마법 객체 생성 및 관리
  • MagicBook: 마법 쿨타임, 타겟 탐색, 시전 처리
  • TargetSystem / TargetScanner: 단일/다중/랜덤/위치 기반 타겟팅 처리
  • CommonBattleManager: 데미지 정보 생성, 치명타, 속성, 부가 효과 계산
  • MonsterAbilityHandler: 몬스터 공격 능력 쿨타임 및 거리 조건 처리

AchievementSystem 구현

  • 업적 데이터 정의 및 조건 체크 구조 구현
  • 업적 달성 시 팝업 UI 표시
  • 로컬 저장 및 클라우드 저장 대응
  • 게임 진행 상황에 따른 업적 상태 갱신
  • Steam 출시 프로젝트의 게임 시스템 개발 참여

기술적 문제

로그라이크 액션 게임 특성상 마법, 몬스터, 타겟팅, 데미지 계산 규칙이 계속 확장될 수 있었습니다.

해결 방식

타겟 탐색, 데미지 계산, 마법 시전, 몬스터 공격 처리를 각각 독립된 클래스로 분리했습니다. 새로운 마법 효과나 타겟팅 옵션이 추가되어도 기존 전투 흐름을 크게 수정하지 않도록 구조화했습니다.

게임 클라이언트 역량으로 연결되는 지점

출시 게임의 전투 로직, 타겟팅, 보상 피드백 구조를 다루며 실제 플레이 감각과 시스템 확장성을 함께 고려했습니다. 전투 시스템과 업적 시스템은 게임의 반복 플레이 경험과 직접 연결되는 핵심 클라이언트 영역입니다.

Representative Project 03

Rfice MyRoomEditor

런타임 3D 공간 편집 시스템

게임식 해석

게임의 하우징 시스템, 맵 에디터, 런타임 배치 시스템과 유사한 3D 상호작용 구조입니다.

플랫폼WebGL, iOS, Android
역할Unity 클라이언트 개발
담당 시스템MyRoomEditor
주요 기술Unity, C#, Input System, Raycast, MVP, Clean Architecture, Zenject

게임 클라이언트 관점의 의미

MyRoomEditor는 일반 SaaS 기능이지만, 게임 개발 관점에서는 런타임 레벨 에디터, 하우징 시스템, 배치형 콘텐츠 편집 시스템과 유사합니다. 사용자가 3D 공간에서 오브젝트를 선택, 배치, 이동, 회전, 색상 변경, 이미지 적용할 수 있는 인터랙티브 시스템을 구현했습니다.

담당 업무

  • 3D 공간 내 오브젝트 배치, 선택, 이동, 회전 기능 구현
  • Raycast 기반 오브젝트 선택 및 배치 가능 영역 검증
  • 상태 기반 편집 모드 구조 구현
  • 오브젝트 타입별 편집 가능 기능을 인터페이스로 분리
  • 카메라 이동, 줌, 회전 등 에디터 조작 입력 처리
  • 오브젝트 색상 변경, 이미지 업로드, 머티리얼 적용 기능 구현

주요 구현 포인트

  • MyRoomEditorState: 배치/편집 상태 전환 관리
  • MyRoomEditorPlacementManager: 오브젝트 생성 및 배치 처리
  • MyRoomEditorPropEditingManager: 선택, 이동, 회전, 삭제 등 편집 처리
  • MyRoomEditorInputController: Input System 기반 입력 이벤트 분배
  • IColorEditableProp / IMoveableProp / IRotatableProp: 기능별 인터페이스 분리
  • RaycastNonAlloc 기반 배치 검증 최적화

기술적 문제

오브젝트마다 가능한 편집 기능이 다르고, 바닥/벽/천장/프레임/스크린 등 배치 규칙도 달랐습니다.

해결 방식

오브젝트 기능을 인터페이스로 분리하고, 편집 상태를 State 구조로 관리했습니다. 특정 오브젝트가 이동 가능한지, 회전 가능한지, 색상 변경 가능한지 런타임에 판단하고, UI와 편집 로직이 해당 기능만 노출하도록 구성했습니다.
